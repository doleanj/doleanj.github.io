THE QUESTION

How do you multiply teams’ AI capacity without becoming their bottleneck?

My answer: a kit they use themselves, not projects we run for them.

The human decides, the machine executes

1. Pickup

The session reads the state left in the repository.

2. Design

Human gate: the human approves the spec.

3. Build

Branch, code and tests on a throwaway instance.

4. Ship

The PR is merged when tests are green.

5. Verify

Automatic deployment, then a real check.

6. Handoff

State rewritten, lessons logged for next time.

A session resumes in 7 tool calls instead of 16: the context lives in the repo, not in someone’s head.

The agent has no direct access to production

1. Dry run

The agent prepares a tested script. It runs as a dry run, after a backup.

2. Approval

A human reviews the dry run and approves the real run, bound to that dry run.

3. Audit trail

The run leaves an audit trail. A read-only check mode verifies the result.

The agent’s autonomy stops where the risk starts. That is what makes it acceptable.
